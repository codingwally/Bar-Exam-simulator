Both modes require an exact clean candidate, complete suite/source hashes, reviewed changed paths and ancestor, differentiated hosted database proof, the existing sanitized artifact and a reviewed full Cloudflare baseline. The driver invokes the existing release validators directly before creating an account; it also rechecks live suppression immediately before provisioning. Before provisioning, it also requests `GET /auth/v1/settings` on the exact staging Supabase origin using the resolved publishable key, rejects redirects, requires HTTP200 and an enabled email provider, and discards the raw settings. An exact candidate on the specifically trusted Debate branch can therefore be staged without merging or launching publicly, provided the superior task's ownership clearance, exact source/scope, baseline preservation and closed feature/provider/mail gates remain enforced.

No change to a shared/superior workflow follows automatically from this observation.
