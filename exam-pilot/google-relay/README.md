# Private examination delivery relay

This relay runs in the owner's Google account. It writes only to the configured private native Sheet and never changes sharing. The owner copy goes only to `wallyesteban1993@gmail.com` and includes the private collection link. A separate HTML confirmation goes only to the email recorded for that exam taker's submitted attempt: success message, identity/time, numbered answers and a submission reference. It contains no Sheet link, source paper, other students, or owner-only archive attachment. The student browser calls the examination Worker; it never calls this relay.

1. Paste `Code.gs` into the owner's Apps Script project and use `appsscript.json` as its manifest. Set Script Properties `EXAM_RELAY_SECRET` (at least 32 cryptographically random characters) and `GOOGLE_SPREADSHEET_ID`. Keep the secret out of source, URLs, screenshots and logs.
2. Enable the Google Sheets and Drive APIs for the Apps Script project. The supplied manifest enables both services; with the default project Google enables their APIs automatically. A standard Cloud project requires enabling both APIs in its Cloud console. No service account or Sheet sharing is required.
3. Run `verifyRelaySetup` in the editor as the owner and authorize the listed scopes. It checks ownership, private sharing, execution identity, Sheet API access and remaining email quota. It sends no email.
4. Deploy a Web app, execute as the owner, accessible to Anyone. Requests still require a valid HMAC and a timestamp within five minutes. GET returns no examination data. Copy its `/exec` URL.
5. Store Worker secrets `EXAM_RELAY_URL` and `EXAM_RELAY_SECRET` using the same secret. Set `EMAIL_DELIVERY_ENABLED=true` and the matching `GOOGLE_SPREADSHEET_ID` for private owner links. This relay supports owner email and student confirmation without a separate email provider. The service-account and Resend adapters remain available when the relay is not configured.
6. Complete a synthetic examination and verify Sheet, owner-email and student-confirmation outbox jobs. Check the full Sheet content, owner HTML/raw attachment, student HTML numbered answers, recipient boundaries and matching receipt. Configuration alone is not delivery proof.

The relay signs acknowledgements against the exact request digest. Sheet content and its integrity journal are updated together using explicit string cells, with long answers continued at Unicode-safe boundaries. It reads the complete mirror back before success. The per-attempt revision vector prevents older snapshots overwriting newer ones; a final receipt becomes an immutable barrier. A script-wide lock also prevents late provider operations overlapping newer writes. Hidden H1/H2/H3 cells contain mirror, owner-mail and student-mail journals; do not edit these cells. Owner and student messages remain distinct even when the account owner takes the sample exam using their own email.

HTML emails use the same Due Diligence renderer as the alternative provider, with a complete plain-text alternative. The renderer keeps combined HTML and text under 130,000 UTF-8 bytes per part; the relay independently enforces a 150,000-byte safety limit. Continuation parts are labeled and never silently truncate an answer. The owner's complete numbered raw question/answer packet, including blanks and receipt checksums, is partitioned into exact text attachments that reconstruct the whole packet. Student mail uses only its frozen answer allowlist and no attachments. The relay checks the actual remaining daily recipient quota before each new part. Owner and student copies each consume quota. If quota runs out, the job remains pending and resumes remaining parts after reset without repeating accepted parts. Success is reported only after every part is accepted.

Student-mail requests omit mirror values, revisions, raw packets and source data. A student confirmation can run before the separate Sheet backup: it finds or creates a blank attempt tab only to persist H3, and a later mirror writes A:F/H1 while retaining that mail journal. Recipient identity, content hash, final receipt and authenticated request signature are required. The relay rejects a student's mail if it contains the configured private spreadsheet identifier. Existing unrecognized populated tabs remain protected against automatic overwrite.

MailApp reports acceptance for sending. It provides no message identifier, idempotency key or independent inbox delivery confirmation. The relay persists `pending` before each send and `accepted` afterward. A retry never repeats an accepted part. If execution stops between these two journal writes, the job fails with `email_confirmation_required` and requires owner review; it never silently reports success or blindly resends.

To resolve that case, inspect the owner's Sent mail for the exact recipient, receipt, part number and full content or attachment hash. In Script Properties set `EXAM_MAIL_RESOLVE_TAB` to the exact attempt tab title, `EXAM_MAIL_RESOLVE_PART` to its 1-based part number, `EXAM_MAIL_RESOLVE_TARGET` to `owner_email` (default) or `student_receipt`, and `EXAM_MAIL_RESOLVE_ACTION` to `confirm` only when the sent copy was verified. Use `retry` only when the owner intentionally accepts the risk of a duplicate. Run `resolvePendingOwnerEmail` in the owner editor, then retry the failed outbox job. The helper removes all resolution properties. Never resolve from a student request.

Quota or transfer failures leave the durable outbox pending/failed and never change the student's receipt. Google currently documents 100 email recipients per day for consumer accounts, six minutes per execution, and 200 KB body/25 MB attachments per message. A multipart copy consumes one daily recipient per part. The Worker caps relay transfers at 40 MiB; the relay additionally caps a message set at 300 parts, mail-journal cells at 40,000 characters and each owner archive attachment at 20 MiB. These limits fail visibly rather than truncating content. Unusually large examinations need an additional archive channel. The primary database and receipt remain authoritative. This free relay does not provide a contractual delivery SLA.
