# Owner-only Google backup relay

This relay runs in the owner's Google account. It writes only to the configured private native Sheet and emails only `wallyesteban1993@gmail.com`. It never changes sharing. The student browser calls the examination Worker; it never calls this relay.

1. Paste `Code.gs` into the owner's Apps Script project and use `appsscript.json` as its manifest. Set Script Properties `EXAM_RELAY_SECRET` (at least 32 cryptographically random characters) and `GOOGLE_SPREADSHEET_ID`. Keep the secret out of source, URLs, screenshots and logs.
2. Enable the Google Sheets and Drive APIs for the Apps Script project. The supplied manifest enables both services; with the default project Google enables their APIs automatically. A standard Cloud project requires enabling both APIs in its Cloud console. No service account or Sheet sharing is required.
3. Run `verifyRelaySetup` in the editor as the owner and authorize the listed scopes. It checks ownership, private sharing, execution identity, Sheet API access and remaining email quota. It sends no email.
4. Deploy a Web app, execute as the owner, accessible to Anyone. Requests still require a valid HMAC and a timestamp within five minutes. GET returns no examination data. Copy its `/exec` URL.
5. Store Worker secrets `EXAM_RELAY_URL` and `EXAM_RELAY_SECRET` using the same secret. Set `EMAIL_DELIVERY_ENABLED=true` for owner email. Keep any existing Resend configuration if student receipt emails are required; this relay never sends to students. The service-account and Resend adapters remain available when the relay is not configured.
6. Complete a synthetic examination and verify both outbox jobs, full Sheet content, numbered raw email bodies, matching attachments and receipt checksum. Configuration alone is not delivery proof.

The relay signs acknowledgements against the exact request digest. Sheet content and its integrity journal are updated together using explicit string cells, with long answers continued at Unicode-safe boundaries. It reads the complete mirror back before success. The per-attempt revision vector prevents older snapshots overwriting newer ones; a final receipt becomes an immutable barrier. A script-wide lock also prevents late provider operations overlapping newer writes. Hidden H1/H2 cells contain integrity and mail journals; do not edit these cells.

Email bodies contain the complete numbered raw question/answer packet, including explicit blanks, receipt and answer checksums. Packets are split at 140,000 UTF-8 bytes per part, below the consumer 200 KB body limit. Each part also has an exact text attachment and part/whole-packet hashes. All recipients are the owner. The relay checks the daily recipient quota before each new part. If it runs out, the job remains pending and resumes the remaining parts after the quota resets, without resending already accepted parts. It reports success only after every part has been accepted.

MailApp reports acceptance for sending. It provides no message identifier, idempotency key or independent inbox delivery confirmation. The relay persists `pending` before each send and `accepted` afterward. A retry never repeats an accepted part. If execution stops between these two journal writes, the job fails with `email_confirmation_required` and requires owner review; it never silently reports success or blindly resends.

To resolve that case, inspect the owner's Sent mail for the receipt, part number and exact attachment hash. In Script Properties set `EXAM_MAIL_RESOLVE_TAB` to the exact attempt tab title, `EXAM_MAIL_RESOLVE_PART` to its 1-based part number and `EXAM_MAIL_RESOLVE_ACTION` to `confirm` only when the sent copy was verified. Use `retry` only when the owner intentionally accepts the risk of a duplicate. Run `resolvePendingOwnerEmail` in the owner editor, then retry the failed outbox job. The helper removes the three resolution properties. Never resolve from a student request.

Quota or transfer failures leave the durable outbox pending/failed and never change the student's receipt. Google currently documents 100 email recipients per day for consumer accounts, six minutes per execution, and 200 KB body/25 MB attachments per message. A multipart copy consumes one daily recipient per part. The Worker caps relay transfers at 40 MiB instead of truncating content; unusually large examinations need an additional archive channel. The primary database and receipt remain authoritative. This free relay does not provide a contractual delivery SLA.
